В каждой папке два файла.

**`points.json`** содержит объекты категории в прямоугольнике вокруг города в том виде, в каком их отдаёт сервис Overpass API. Запрос, ответ на который лежит в файле, записан в поле `query` в начале файла. У аптек Казани он такой:

```
[out:json][timeout:90];
nwr["amenity"="pharmacy"](55.60,48.80,55.95,49.40);
out center tags;
```

Строка `nwr` берёт объекты всех трёх видов: точки (`node`), контуры зданий (`way`) и составные объекты (`relation`). У двух последних координаты нет, есть только контур. Строка `out center` подставляет вместо контура его центр, поэтому у таких объектов вместо полей `lat` и `lon` стоит поле `center`. Четыре числа в скобках задают прямоугольник: южная широта, западная долгота, северная широта, восточная долгота. Прямоугольник только ограничивает выгрузку и с районом не связан.

**`district.geojson`** содержит границу района в формате GeoJSON, в том виде, в каком её отдаёт сервис Nominatim. Номер района в OpenStreetMap записан в поле `osm_id`, и по нему границу можно открыть на карте, например `https://www.openstreetmap.org/relation/2133467`.

Наборы вырезаны из выгрузки OpenStreetMap от 2 октября 2026 года, сделанной сервисом Geofabrik, и это время записано в поле `timestamp_osm_base`. Версию данных фиксирует сам файл. Карту с тех пор могли поправить, поэтому повторный запрос к Overpass вернёт немного другие объекты, а ваши числа воспроизводятся на файлах из каталога. Номера объектов от правок не меняются, и любой объект открывается на openstreetmap.org по номеру: `https://www.openstreetmap.org/node/11668511289`.

Каждый набор проверен заранее. В нём от 200 до 5000 объектов: меньше двухсот, и оболочку с ближайшей парой видно на глаз, а больше пяти тысяч, и независимая проверка перебором пар становится неудобной. Район содержит часть объектов, но не все, иначе вопрос «сколько внутри» вырождается в «все» или «ни одного». Граница района не пересекает сама себя ни в градусах, ни после округления, и ни один объект не лежит точно на ней.

**Свои данные вместо каталога.** Можно выгрузить данные самостоятельно: другой город, другую категорию, другой район. Точки берутся таким же запросом к Overpass, отправленным на `https://overpass-api.de/api/interpreter` или выполненным на сайте [overpass-turbo.eu](https://overpass-turbo.eu). Метку категории можно найти в [справочнике тегов OpenStreetMap](https://wiki.openstreetmap.org/wiki/RU:Map_features). Граница района берётся из Nominatim по номеру отношения: найдите район на openstreetmap.org поиском и возьмите номер из адреса страницы. Для Советского района Казани файл отдаёт запрос `https://nominatim.openstreetmap.org/lookup?osm_ids=R2133467&polygon_geojson=1&format=geojson`. К своим данным три требования.

* **В запросе к Overpass стоит дата**, например `[out:json][timeout:90][date:"2026-09-01T00:00:00Z"];`. Она просит данные в том виде, в каком они были на эту дату, и повторный запуск через месяц вернёт те же объекты. Без даты числа в отчёте перестанут воспроизводиться после первой же правки карты. Фильтр по области города (`area`) с датой не работает, поэтому ограничивайте выборку прямоугольником.
* **Объём и район отвечают тем же условиям, что и наборы каталога.** От 200 до 5000 объектов, в районе часть из них, но не все.
* **Оба файла лежат в репозитории, а текст запроса и ссылка на район — в отчёте.** Файл, выгруженный повторно, по байтам не совпадёт с вашим, потому что в ответ Overpass вписывает время запроса. Совпасть должны сами объекты.

Серверы Overpass бывают перегружены часами, поэтому выгружайте данные заранее. При запросе через `curl` укажите заголовок `User-Agent` с любым названием, без него сервер отвечает ошибкой 406. Если основной сервер не отвечает, отправьте запрос на зеркало, например `https://overpass.private.coffee/api/interpreter`. Зеркала бывают отстающими. Поле `timestamp_osm_base` в начале ответа показывает, до какой даты у сервера есть данные. Если она раньше даты в запросе, сервер без всякой ошибки вернёт карту на дату `timestamp_osm_base`, и повторить ваши числа на основном сервере не получится.
